## 环境、数据和计时方法

Docker Engine 29.8.2，Linux x86_64，Docker 可用 16 CPU、8,164,827,136 字节内存；容器没有单独 CPU 配额。镜像 `eyes-clean-control:20261011` / `sha256:4775a9362087d827e6131e51be73c0e970aaf88b247d606c9142c892daa2ab82`，只读挂载本轮 Eyes 源码和原评分器。实际 Python 3.14.7、PostgreSQL 18.6、FastAPI 0.142.2、SQLAlchemy 2.0.54、psycopg 3.3.6、uvicorn 0.54.0、Pydantic 2.13.5，迁移 `0005_reconciliation`。这是已有锁定镜像的性能测量，不另称无缓存部署验收。

本轮数据库使用新卷、新网络，API 18067 / PostgreSQL 55447；最终同条件复测从**同一原完整备份重新恢复**到独立 `eyes_matched`，API 18069 和新的空 Runner 卷，不在基线已经增加评分历史的库上比较。两侧初始均为 13 实验、39 CaseRun、20 Attempt、341 Event、47 ready 产物、86 清单、25 ScoreRun、17 报告、62 WorkItem。恢复副本保留历史项目 UUID/证据归属；新签发副本凭据，旧 Runner 凭据在副本撤销。项目评分额度仅在副本设为 4；服务全局评分额度 4，执行槽 0，poll=2 秒、租约 60 秒、原评分截止 40 秒、证据保留天数 0。原三任务为 fix-mean / integer-cli / stable-unique，使用原 `deta_code` 评分器和真实冻结代码产物，不修改任务、评分器或期望。

读取用宿主机 httpx、复用连接、有界并发、无自动请求重试，客户端 `perf_counter` 计收到完整响应的耗时。每档 120 GET，四端点各 30；实际仅 0.60～0.98 秒，因此是**短突发读取样本**。没有持续饱和测试、网络跨机测试或重复统计显著性。

评分等待从 WorkItem.created_at 到 claim 计算；claim 时间由固定 ScoreRun.deadline 减原 40 秒截止得到。执行/评分路径耗时从 claim 到 Runner 日志中的真实 `score-result HTTP 200`，包含下载、独立评分进程和完成上报，不是纯评分函数 CPU 时间。吞吐为 6 次 /（最后一次完成确认－首次 claim），批次另记录提交到观察到全完成的耗时。Docker 日志时间和数据库时间同来自本机 Linux 环境，仍有日志排队误差；采集查询每约 100 ms，资源每约 10 秒，实际 301 秒中 2177 次数据库采样、24 次资源采样。采集本身有开销，不能按理想间隔换算为完整逐时追踪。

Runner 采集器在真实 run 中包装 recover/reap/collect/size、async flush、实际文件 atomic_write 和请求计时；同时每 50 ms 测事件循环唤醒延迟。不替换业务结果、网络响应或持久化操作。flush 的总耗时含 await 网络及 lane 锁，不能把它全算成同步循环阻塞。聚合的“最差窗口 p95”是十秒窗口 p95 的最大值，不能称全程 p95。

用户随后明确 **1 RMB** 模型预算。当前 bridge 只记录执行后的 token usage，没有累计金额硬上限或调用前费用校验；max_iterations 不能保证人民币费用上限。因此本轮新增模型请求和模型费用均为 **0**，保留该预算，不将重新评分冒充 Agent 执行压测。

## 资源、短时覆盖和剩余长期条件

基线观测 **301.04 秒**，包括短读取、18 次评分、48 个回滚报告事务和空闲 Runner；API 曾短暂停止再启动，因此不是全组件连续无故障五分钟，更不能称多日稳定。Runner 运行中实际领取请求失败后恢复为 HTTP 200；这是空闲连接恢复，没有待发 outbox 或活跃远端任务，不代替完成补传/响应丢失恢复。采样中 Runner last_seen 最大年龄 5.14 秒，未出现新的 unknown；已有两个 unknown 的额度没有释放。

资源采样：API CPU 最大 85.87%、内存约 100.7→116.3 MiB，重启后约 80～83 MiB；PostgreSQL CPU 最大 13.24%、内存约 65～90 MiB；Scheduler 最大 0.31%、约 59～61 MiB；空闲四槽 Runner 约 36～40 MiB。短评分过程中一槽 Runner 的 CPU 采样 33.85%、内存 81.64 MiB；其他档采样没有覆盖每个瞬时峰值，不称峰值上限。停止时 Docker 的 0B 样本不作为内存回落证据。数据库 11,728,575→11,843,263 字节，包含追加评分/WAL 与分析统计的影响；BlockIO 是 Docker 累计计数，不能解释成磁盘延迟。宿主机最低剩余约 129 GiB。

基线状态卷一次实测 421368 字节（约 0.40 MiB）、134 文件、18 个评分工作目录；outbox 采样 pending/rejected=0、空闲大小 82 字节。完成评分的 trace/journal 被保留是当前机制，reap 仅移除评分 workspace，**没有自动 Runner 评分记录保留上限**；长期连续评分会增长，需要部署者明确私有 journal 保留策略。只运行 maintain preview，无到期 Attempt/pending/垃圾；retention_days=0 不自动过期，不能称本轮覆盖自动到期/清理失败。已有正式单 Attempt 过期验收沿用部署记录。本轮没有大 outbox、磁盘耗尽、慢盘、重传积压或丢弃正向样本；新增评分只证实本次无此类日志/错误，不声称这些分支已测完。
